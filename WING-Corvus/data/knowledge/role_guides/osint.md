# OSINT 题型分工指南 (Role Guide)

> 维护规则: 本文件**只改不增** — 不新增 skill, 只在现有段落上完善; 篇幅 ≤4KB.
> 注入规则: 按当前阶段 (P1~P4) 只注入对应段落, 压缩上下文避免分心.

## P1 侦查 (Recon)

**目标**: 识别信息源 (图片/文本/账户/网址/社交线索).

**工具链**: `osint_tool` (exiftool/steghide) → `web_search` (通用技术查阅) → `osm_geocode` (地理定位) → `ssh_exec` (工具探测).

- 图片: EXIF 元数据 (GPS/相机/时间) → 地理定位 (osm_geocode 地名)
- 文本线索: 用户名/ID/时间戳/坐标 → 确定搜索方向
- 社交/平台: GitHub/社交媒体/域名注册信息 → 记录每步来源
- 合规搜索: 只查通用技术/平台用法, 不搜本题题解 (护栏)

**推进标准**: 至少一条可追踪线索 (位置/账户/平台) → 进入 P2.

## P2 关联溯源 (Identify)

**目标**: 沿线索逐层关联, 收敛到唯一答案.

**工具链**: `web_search` (通用查询) → `ssh_exec` (curl/API) → `osint_tool` (平台数据).

- 每步都要记录证据来源与时间; 多条线索交叉验证 (不要只信单源)
- 平台 API: GitHub API 搜仓库/用户/提交; 域名 whois; 搜索引擎高级语法
- 图片搜索: 用图像特征反查来源 (不依赖肉眼描述)

**推进标准**: 线索收敛到具体对象 (人/地点/组织/URL) → 进入 P3.

## P3 确认答案 (Exploit)

**目标**: 验证答案并提取 flag (若需提交内容).

**工具链**: `web_search` → `ssh_exec`/`ssh_python` (访问验证) → `osm_geocode`.

- 答案必须可验证: 用多个来源交叉确认同一结论
- 若答案是 flag 的一部分/URL/坐标 → 精确提取并格式化 (flag 格式照题面)
- 远程/交互: 提交答案观察响应

**推进标准**: 答案经工具验证 (多源一致) → 进入 P4.

## P4 验证提交 (Validate)

**目标**: 确认答案/flag 真实并提交.

- flag/答案必须基于工具观测, 不猜; 多源交叉验证过的才提交
- 无工具调用直接 Final Answer = 幻觉 (系统会拒绝)
- 拿不到 → Final Answer 老实报告已确认/未确认的信息, 不编造
