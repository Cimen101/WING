## 三、发现的问题与修复

- 现象: 复用上一轮 `data/bus/ghmid_*` 目录, 旧 directive (seq 1-3, 无 phase/forbidden) 混入新运行, 战略层 cursor=0 会先消费旧消息再被新消息覆盖 (任务禁忌短暂缺失窗口).

### 问题 2 (观察, 非缺陷): 单路先行未触发
- 本题三路侦查均衡推进 (step 5-8 都深入反汇编), 无"某路完成其他路未完成"的错位场景, 故单路先行未触发.
- 单路先行逻辑已由单测覆盖 (24 项含 3 个先行场景: P2 先行/flag 直达 P3/先行升级 P3), 均通过.
- 说明: P1 阶段 agent 天然深入 (三路在 P1 就还原了变换函数), 90s 限时快速切入 P2 收尾, 实际效率高.

### 问题 3 (观察): P1 超时兜底实际触发
- 三路均未汇报 recon_done (战略层巡查未判 p1_done), 依赖 90s 限时兜底强制推进. **验证了 P1 限时兜底是必要保障** — 若无限时, 三路可能长期停在 P1 等待 recon_done.
