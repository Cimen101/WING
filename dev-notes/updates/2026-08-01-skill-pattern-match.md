# 更新：Skill 套路匹配机制改进（题目名匹配 → 套路特征匹配）

- 日期：2026-08-01
- 版本：WING-Goose（雁阵）——旧版本迭代更新
- 涉及模块：Skill 调度 / 套路匹配（Sprint 28）

## 背景

Skill 库的套路匹配此前基于「题目名称」字符串匹配：只有题目名与套路登记名一致时才命中，跨题复用能力差——同一套路换一道新题（不同名字）即无法命中，只能回退到通用流程，耗时成倍增加。

## 变更内容

匹配机制从「题目名称匹配」改为「套路特征 pattern_features 匹配」：

- 每个 Skill 登记一组 pattern_features（套路特征描述，如 RSA 小模数、公共模数、小私钥指数、内存 XOR 等可观测特征）；
- 匹配时抽取当前题目的特征并与 pattern_features 比对，命中后注入对应套路；
- 同一套路多次命中时按版本合并去重（version 1 → 3），避免重复注入。

## 验证（三次运行）

| 运行 | 场景 | 耗时 | 对比 |
| :-- | :-- | :-- | :-- |
| 1 | 原题（未命中具体 skill） | 85.0s | 基准：费马分解超时后回退 crypto_rsa 通用套路 |
| 2 | 同名题改名 | 7.3s | 提速 11.6x |
| 3 | 跨题 UDCTF | 8.9s | 提速 9.6x，验证跨题泛化 |

- 三次运行命中同一 skill；skill 版本号 1 → 3，合并去重生效，未出现重复注入。

## 涉及套路

- crypto：RSA 小模数分解套路（典型场景：模数可直接分解——相近素数 / 费马分解可达；代表性题目如 picoCTF 2018 Super Safe RSA 等历史题目，此处以泛化描述记录，不涉及具体题目数据）。

## 影响面

- 仅影响 Skill 匹配与注入环节；不改动解题主流程与 flag 验证链路。
- 收益：跨题泛化能力显著提升，同类题目首次命中即进入专用套路，平均提速约 10 倍。
