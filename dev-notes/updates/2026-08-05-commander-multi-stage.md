# 更新记录：总指挥（Commander）多阶段升级 — 从被动监听者到多阶段自适应调度器

- 日期：2026-08-05
- 版本：WING-Corvus（渡鸦）——最新版本小版本更新

## 变更背景

基于 nss_2800（EasyP，PHP 文件上传）全量轨迹复盘发现：三路 agent 在解空间上严重趋同——全部选择 basename 绕过方向，最终错过非 ASCII 截断这一更优路径。根因在于总指挥此前仅充当"被动监听者"（汇总结果、下发粗粒度分工），缺乏对解题进程的阶段化编排与差异化调度能力。

## 变更内容

### 1. 解题流程阶段化（P1 ~ P4）

| 阶段 | 名称 | 职责 |
| :-- | :-- | :-- |
| P1 | 侦查 | 题目类型识别、附件/源码/服务端点摸底、公开参数提取 |
| P2 | 漏洞识别 | 依据 P1 情报生成候选攻击面，收敛到 1~2 个高置信方向 |
| P3 | 利用 | 针对选定方向构造并执行攻击，产出可验证结果 |
| P4 | 验证 | 对 P3 结果做确定性验证，防止假阳性提交 |

### 2. 每阶段按风格差异化分配任务（避免路径趋同）

同一阶段内三路不再领同一份工，而是按风格拆解互补：

- **conservative**：以系统化解析与已知工具/内置攻击库为主，走稳路径；
- **aggressive**：快速试跑经典攻击与黑名单绕过，负责"先手试错"；
- **innovative**：探索非常规信息源与绕过思路，负责"打开新方向"。

阶段切换时重新按当前状态分配子任务，确保三路覆盖解空间的不同区域。

### 3. 阶段切换 / 回退明确条件

- 前向切换：当前阶段目标达成（如 P1 产出关键情报、P2 收敛出方向）即切换；超时无产出也强制切换并记录原因；
- 回退：P3 利用失败且判定为情报不足时，回退到 P2 甚至 P1 重新侦查，而不是在同方向空转。

### 4. 卡住检测与干预

- 连续 N 步无有效进展（无新事实、无工具成功结果）判定为卡住；
- 卡住后总指挥介入：调整该路风格/任务，或派兄弟路从旁提供线索；
- 步数与时间双重上限兜底（默认 80 步 / 1800s）。

### 5. 创新型强制发散

- 当三路提交方向趋同（如均走 basename 绕过）时，总指挥强制对 innovative 路下发发散指令，切换攻击向量或重新侦查；
- 发散产生的候选方向由 P4 验证收敛，避免过度发散浪费算力。
