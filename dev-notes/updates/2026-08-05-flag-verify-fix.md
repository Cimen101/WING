# 更新：提交前 flag 验证器增强（W32-flag-verify）

- 日期：2026-08-05
- 版本：WING-Corvus
- 文件：`ctf_agent/agent/flag_verify.py`

## 背景

WING-Corvus 大幅迭代后首次完整测试（SU_RSA，crypto/hard）发现：直接单 agent 求解时，
系统曾把「猜测的假 flag」判定为 `success=true`，存在幻觉假阳性。

## 变更内容

### 1. 新增「自导自演」代码机制检测

提交前验证新增一条硬规则：**flag 若同时出现在该步的「工具输入」（agent 自己写的
脚本 / 命令）中，判定为编造，拒绝提交。**

- 根因：agent 可能把猜测的 flag 硬编码进脚本再执行，脚本 stdout 输出该 flag，
  使旧的「flag 出现在 Observation」检查被绕过（输出只是脚本 echo 了输入）。
- 真实解法中，flag 应只出现在工具**输出**（解密结果 / 文件读取 / 靶机响应），
  工具输入中不应包含 flag 文本。

### 2. LLM 审查改为 fail-closed（保守拒绝）

- 旧行为：LLM 审查输出无法解析 / 调用异常时「视为通过」（降级不阻断）。
- 新行为：无法解析 / 异常时「保守拒绝」，返回明确原因让 agent 重新基于真实观测取证。
- 目的：避免「审查不可用 → 放行」的通道成为幻觉 flag 的漏网路径。

### 3. LLM 审查 prompt 增加自导自演判定标准

- 判定标准第 4 条：flag 只出现在 agent 自己构造并执行的脚本 stdout 中，
  且脚本输入/内容本身硬编码了 flag 文本（未从附件/靶机真实提取）→ 判定为编造。

## 验证

新增单元验证（3 场景，仅代码机制，不调 LLM）：

| 场景 | 期望 | 结果 |
| :-- | :-- | :-- |
| 自导自演：脚本输入含假 flag，stdout echo 出该 flag | 拒绝 | 拒绝 ✅ |
| 正常：脚本从附件参数解密输出真实 flag，输入不含 flag | 放行 | 放行 ✅ |
| 凭空编造：flag 未出现在任何观测 | 拒绝 | 拒绝 ✅ |

## 影响面

- 仅影响提交前的 flag 验证环节；不改变 agent 推理、工具调用与 swarm 协作逻辑。
- swarm 模式（带确定性数学验证）不受影响，本次修复主要封堵单 agent 模式的幻觉通道。
