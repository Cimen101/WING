# 更新记录：Reverse 泛化能力架构优化方案（基于 5 题 hard reverse 0/5 根因分析）

- 日期：2026-08-11
- 版本：WING-Corvus（渡鸦）——最新版本小版本更新

## 背景

Google CTF hard reverse 专项测试 5 题 0/5（详见 `tests/2026-08-08-gctf-hard-reverse.md`），失败根因归纳为三个单点能力缺失：

1. 统计 / 模式推理缺失
2. 环境依赖预检缺失
3. 结构化逆向知识缺失

本方案据此设计 Reverse 泛化能力的架构增强。

## 设计原则

**不新建独立子系统，所有增强均作为现有组件的能力扩展。**

先对候选改动做架构审计：砍掉 5 个过度设计项，仅保留 3 个高杠杆增强。

### 审计砍掉的过度设计项

| 项 | 砍掉理由 |
| :-- | :-- |
| 多模型路由层 | 引入新的调度复杂度，收益未经验证，现有总指挥分工已可覆盖 |
| 独立逆向引擎 RPC | 与现有工具链重复，额外维护常驻服务得不偿失 |
| 工具输出增强器 | 过度抽象，输出增强可并入具体工具实现 |
| 多模态验证器 | 题目场景以文本 / 字节码为主，收益有限且成本高 |
| 动态分工引擎 | 现有固定分工 + 巡查干预已够用，动态化收益不明显 |

## 保留的 3 个增强

### ① binary_deep_analyze 新增 mode=crypto 与 mode=stat

- `mode=crypto`：算法指纹识别
  - AES（S-box 特征）、RSA（N/e 参数结构）、Paillier、TEA（delta 常量）、ECC（曲线参数）等常见算法指纹自动匹配
  - 解决"ilovecrackmes 将 Paillier 误判为 RSA"这类参数形状相似导致的误判
- `mode=stat`：统计推理
  - 字节频率、信息熵、置换表推导等统计型分析
  - 解决"x86perm 置换表推导"类纯统计题目

### ② 容器初始化离线环境预检

- 附件依赖扫描：对附件执行 ldd 级依赖扫描，识别 GLIBCXX、MAME、多架构模拟器等运行依赖
- 自动解决：在容器初始化阶段自动安装 / 配置缺失依赖
- `.env_report` 标记：预检结果写入环境报告标记，供 agent 在动态验证阶段直接引用
- 解决"ilovecrackmes / arcade / multiarch-1 缺环境导致动态验证断链"

### ③ 知识库新增 structured/ 结构化知识层

- `algorithm_fingerprints/`：算法指纹 JSON（AES / RSA / Paillier / TEA / ECC 等特征）
- `architecture_guides/`：架构 / 虚拟机识别指南（多架构字节码、MAME 等）
- `environment_solutions/`：常见环境依赖问题的标准解法 JSON
- 以检索式注入方式使用，缓解"结构化逆向知识不足"造成的模型记忆依赖

## 预期收益

| 阶段 | 预期解题率 |
| :-- | :-- |
| 现状（5 题 hard reverse） | 0/5 |
| Step1（工具增强 + 环境预检） | 1-2/5 |
| Step3（结构化知识层就位） | 3-4/5 |

## 验证方式

- 以 gctf hard reverse 5 题为回归集，按 Step1 → Step3 分阶段验证
- 工具单测：crypto 指纹样例集 / stat 置换表样例集
- 环境预检在容器初始化测试中覆盖依赖缺失场景
