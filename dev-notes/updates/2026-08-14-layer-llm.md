# 更新记录：分层 LLM 覆盖（Sprint 39，per-layer provider/model）

- 日期：2026-08-14
- 版本：WING-Corvus（渡鸦）——主线
- 范围：按层（commander/strategy/tactic）独立指定 LLM provider/model 的选择机制

## 背景

DeepSeek-V4-Pro-0813 正式版（8/13 上线）Agent 能力显著提升，拟测试"总指挥+战略层用官方 pro、战术层保持 zen flash"的分层组合，对照全 flash。此前所有层共用全局 LLM 路由，无法按层差异化。

## 变更内容

### 1. 分层 LLM 选择机制

- **`config.py`**：新增 `layer_llm_map`（env `LAYER_LLM_MAP`，格式 `layer=provider[:model]` 逗号分隔；layer ∈ commander/strategy/tactic，provider ∈ zen/go/fallback/pro；空 = 全层跟随全局）。
- **`llm/routed.py`**：`__init__` 增 `layer` 参数 + `with_layer()` + `_layer_override()` 解析 + `_call_single_provider()`（**忠实执行指定 provider，不参与降级链**——层指定 pro 就只用 pro，防止偷偷降级 flash 改变成本/质量）；`chat()` 路由入口优先应用层覆盖。
- **`solve.py`**：战术层 `RoutedLLMClient(layer="tactic")`（ReActEngine+FlagVerifier），战略层 `RoutedLLMClient(layer="strategy")`（Coordinator）；CLI 新增 `--layer-llm layer=provider[:model]`（可多次，合并进 LAYER_LLM_MAP）。
- **`swarm.py`**：Commander `RoutedLLMClient(layer="commander")`。
- **`scripts/_verify_run.py`**：新增 `--layer-llm` 参数透传环境变量给 swarm 子进程。
- **默认行为不变**：无 LAYER_LLM_MAP / 无 --layer-llm 时全部层走全局路由。

### 2. 官方 pro 接入与测速结论（关键决策依据）

- 官方 pro 测速（CTF 场景任务）：
  - `none` 档：TTFT 0.7-0.8s，总 9-14s/次，tps 58-70，可用；
  - `high` / `max` 档：输出 100% reasoning_content、content 为空，撞满 max_tokens 截断 → **不可用**（服务端思考不收敛）。
  - **结论**：`_call_single_provider` 强制 pro 层 `reasoning_effort=none`（否则系统 pro 调用必然超时无输出）。
- 端到端验证：`LAYER_LLM_MAP=commander=pro,strategy=pro,tactic=zen:deepseek-v4-flash` → commander/strategy 走官方 pro、tactic 走 zen flash ✓。

### 3. rev-zermatt 对照测试结论（pro 分层 vs 全 flash）

| 配置 | 步数 | 耗时 | 官方 pro 成本 |
|---|---|---|---|
| commander/strategy=pro + tactic=flash | 102 | 40 min | ¥2.88 |
| tactic=pro（战术层） | 244 | 18 min | ¥9.60 |
| 全 flash（对照） | 89 | 40 min | ¥0 |

- 战术层 pro 步骤效率显著提升：aggressive flash 40 分钟 40 步 → pro 11.7 分钟 82 步（~7 倍速度）；但三路均触发 4M token 硬熔断提前终止。
- **结论**：效率提升主要来自 API 响应速度与单步推理深度，但 pro 组输出混入 Claude 风格 XML 工具调用导致约 25% 步为格式错误废步（推理能力无实质增益），且成本不可接受（战术层 pro 单题 ¥9.60）。**决策：模型维持 flash，通过系统/架构升级提升能力（→ Sprint 41）**。
